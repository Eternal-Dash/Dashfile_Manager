# DashFile 插件开发指南

> 适用版本：DashFile 1.0.0 及以后
> 插件 API 版本：`PluginApiInfo.Version = 2`
>
> 插件是普通的 .NET 8 类库（`.dll`），不需要改 DashFile 源码。
> 你可以做：文件/应用/模块右键动作、自定义页面、后台服务、AI 对话面板、逆向分析工具，
> 也可以直接覆盖宿主主题资源来改 UI。

## 0. 示例插件

| 插件 id | 类型 | 能力 |
|---|---|---|
| `com.dashfile.reversetool` | 逆向 | APK 逆向分析：Manifest 解码、签名证书（v1/v2/v3）、DEX 结构/字符串、资源字符串、组件与权限、哈希 |
| `com.dashfile.fastbootflash` | 分区 | Fastboot / fastbootd 刷写、原生 fetch 与 ADB Root 回读、备份包校验恢复；要求 API v2 宿主 |
| `com.dashfile.avbstudio` | AVB | AVB 镜像解析/重签、VBMeta 构建、A/B 批处理、扫描；纯 C#，内置 AOSP 测试密钥 |

- 安装：插件页「安装 .dfp」，或把 `.dfp` 拖进插件页。
- 卸载：插件页选中插件 →「卸载」，可选是否删除插件数据（数据默认在 `%LOCALAPPDATA%\DashFile\plugin-data\<id>`）。
- 源码在 `samples\ReverseToolboxPlugin\` / `samples\AvbStudioPlugin\`，发版时由 `build\build-plugins.ps1` 自动构建为 `.dfp`。
- 插件动作统一收在右键菜单的「插件」子菜单里：单个插件时直接列功能，多个插件时按插件名分组。

## 0.1 用宿主的 UI 组件（别重复造轮子）

### 页签：`SegmentedTabs`（滑块 + 自适应宽度）

插件提供多个页面时，宿主会自动在插件页上方渲染标签条，**不需要自己画**。
插件自己的界面里也要"分段切换"时，直接复用同一份实现（它在 `DashFile.PluginApi` 里，不用引用宿主程序集）：

```xml
<!-- xmlns:papi="using:DashFile.PluginApi.Controls" -->
<Border Classes="card" Padding="6,4" HorizontalAlignment="Left">
  <papi:SegmentedTabs x:Name="Nav" SelectedIndex="0" SelectionChanged="OnNavSelectionChanged">
    <Button Classes="seg tabbtn" Content="解析" />
    <Button Classes="seg tabbtn" Content="签名" />
  </papi:SegmentedTabs>
</Border>
```

- 选中项由**滑块**表示：点击时滑块滑过去，宽度自适应文字长度；
- `SelectionChanged` 给出新下标，页面显隐自己切；
- 也可以数据驱动：`ItemsSource` + `DisplayMemberPath` + `SelectedItem`；
- 外面只包一层 `Border Classes="card"`（或 `seg`），**不要再叠自己的选中背景**，否则会盖住滑块；
- 悬停是即时的微高亮（`Transitions` 为空），移开立刻消失。

### 顶部信息：别自己画标题卡片

插件页外壳已经显示插件名、版本与状态，页面里不用再画一遍大标题。要展示的信息推给宿主：

```csharp
Host.SetHeader(new PluginHeaderInfo
{
    Subtitle = "Android Verified Boot 镜像签名 / 解析 / 批处理",
    Badges   = new[] { "AOSP testkey 内置", "无 Python 依赖", "GPL-3.0-or-later" },
    Status   = "就绪 · 纯 C#",
});

Host.SetStatus("解析中…");   // 只改状态，副标题/徽标保持
```

- 任意线程可调用，宿主切到 UI 线程；
- 只有一个页面的插件不会显示子页标签条（没有切换意义），内容会直接顶到上方。

## 1. 一分钟跑通 Hello 插件

仓库里有完整示例：`samples/HelloPlugin/`。

```powershell
# 1. 编译示例
dotnet build samples\HelloPlugin\HelloPlugin.csproj -c Release

# 2. 建插件目录（插件目录在 DashFile.exe 旁边）
$dst = "DashFile\plugins\com.dashfile.hello"
New-Item -ItemType Directory -Force $dst | Out-Null

# 3. 只需要入口 dll + 清单；Avalonia / 契约程序集由宿主提供
Copy-Item samples\HelloPlugin\bin\Release\net8.0\HelloPlugin.dll $dst
Copy-Item samples\HelloPlugin\plugin.json $dst

# 4. 启动 DashFile → 顶部「插件」→ 重新加载
```

如果插件显示"加载失败"，先看：

- `DashFile\Log\runtime.log`（宿主加载日志，含失败原因）
- `%LOCALAPPDATA%\DashFile\plugin-logs\<插件id>.log`（插件自己的日志）
- 插件页里的红色错误文字

## 2. 目录与清单

每个插件一个目录：

```
DashFile\
  plugins\
    com.example.myplugin\
      plugin.json
      MyPlugin.dll
      （可选）其它依赖 dll / 资源
```

`plugin.json`：

```json
{
  "$schema": "../../docs/plugin.schema.json",
  "id": "com.example.myplugin",
  "name": "我的插件",
  "version": "1.0.0",
  "versionCode": 1000000,
  "author": "你的名字",
  "description": "一句话说明这个插件做什么",
  "tagline": "更短的一句亮点，列表里显示这个",
  "license": "GPL-3.0-or-later",
  "tags": ["纯 C#", "无第三方依赖"],
  "icon": "◆",
  "assembly": "MyPlugin.dll",
  "entryType": "MyPlugin.MyPlugin",
  "apiVersion": 2,
  "minHostVersion": "1.0.0"
}
```

**作者信息由你自己填，宿主原样展示，不会代填或改写。**

| 字段 | 必填 | 说明 |
|---|---|---|
| `id` | 是 | 全局唯一，建议反向域名。禁用状态按 id 保存。 |
| `name` | 是 | 插件页显示名。 |
| `version` | 建议 | 你自己的版本号，副行显示为 `v1.2.3`。 |
| `versionCode` | 否 | 版本序号，`1.2.3` → `1002003`，用于判断新旧。 |
| `author` | **是** | 作者名，插件页副行 `v版本 · 作者 · 状态` 里原样显示。 |
| `authors` | 否 | 多人合作时填 `"甲 / 乙"`，填了就优先于 `author`。 |
| `description` | 建议 | 一句话说明。 |
| `tagline` | 否 | 更短的亮点短语；填了列表第三行与详情页副标题都用它。 |
| `tags` | 否 | 能力徽标数组，显示在详情页头部（最多 6 个）。 |
| `icon` | 否 | 列表图标，一个 emoji 或 1~2 个汉字；不填是 `◆`。 |
| `license` | 否 | 例如 `GPL-3.0-or-later`。 |
| `homepage` | 否 | 主页 / 仓库地址。 |
| `assembly` | 建议 | 入口 dll 文件名；省略时找目录里唯一 dll。 |
| `entryType` | 建议 | 实现 `IDashFilePlugin` 的类型全名；省略时自动找。 |
| `apiVersion` | 是 | 编译时使用的 API 版本，当前为 `2`。 |
| `minHostVersion` | 否 | 要求的最低 DashFile 版本；**改宿主版本号时，示例插件与已发布插件必须同步改**，否则宿主会以「插件要求 ≥ x.y.z，当前 …」拒载。 |
| `enabled` | 否 | 默认是否启用；用户在插件页切换后状态存本机，不改清单。 |

> 版本不匹配是最常见的「插件突然消失」原因：宿主 `AppInfo.Version` 降/升之后，旧 `.dfp` 里的
> `minHostVersion` 若高于宿主，插件会被直接跳过（`Log\plugins.log` 里能看到「已加载 0 个」）。
> 发版前用 `build\build-plugins.ps1` 重编一次分发包即可。

### 从零开始（脚手架）

```powershell
powershell -ExecutionPolicy Bypass -File build\new-plugin.ps1 `
    -Id com.me.dexhelper -Name DexHelper -Author "你的名字"
```

会在 `samples\<名字>\` 生成 `csproj` + `Plugin.cs` + `plugin.json` + 说明。
清单里已经带好 `$schema`，VS Code 打开会自动补全字段、校验类型（schema 在 `docs/plugin.schema.json`）。

生成后：
1. 写你自己的界面与动作（`Plugin.cs`）；
2. 改清单里的 `name` / `author` / `version` / `tagline` / `icon`；
3. 打包成 `.dfp`（把插件加进 `build\build-plugins.ps1` 的 `$plugins` 列表最省事）。

> 插件目录可以在两个位置，宿主都会扫描：
> 1. `DashFile.exe` 同级的 `plugins\`（推荐，便携）
> 2. `%LOCALAPPDATA%\DashFile\plugins\`（用户级，.dfp 安装默认落这里）
>
> 两处同名 id 时**前者优先**。开发时注意别在 `bin\...\plugins` 里留下旧副本，会盖住新装的版本。

## 3. 最小插件

```csharp
using DashFile.PluginApi;

public sealed class MyPlugin : PluginBase
{
    public override PluginMetadata Metadata => new()
    {
        Id = "com.example.myplugin",
        Name = "我的插件",
        Version = "1.0.0",
        Author = "you",
        Description = "示例",
    };

    protected override Task OnInitializeAsync(CancellationToken ct)
    {
        Host.AddPage(PluginPage.FromControl(
            "main", "我的面板",
            host => new Avalonia.Controls.TextBlock { Text = "Hello DashFile" },
            "一句话说明", "◆"));

        Host.AddAction(new PluginAction
        {
            Id = "hello-file",
            Title = "我的插件：处理这个文件",
            Targets = new[] { PluginTargetKind.File },
            ExecuteAsync = async (target, token) =>
            {
                var r = await Host.Device.ShellAsync(
                    "ls -l " + PluginShell.Quote(target.Path), true, token);
                await Host.Ui.ShowMessageAsync("结果", r.All, token);
            },
        });

        return Task.CompletedTask;
    }
}
```

## 4. 宿主能力（IPluginHost）

`Host` 在 `PluginBase` 里已经帮你保存。所有耗时操作都接受 `CancellationToken`。

| 属性 | 能做什么 |
|---|---|
| `Host.Device` | 设备是否连接 / 是否 root / 型号 / shell / 二进制读写 / 上传下载 / 临时文件 |
| `Host.Files` | 文件页当前目录、选中项、列目录、读写、改权限 |
| `Host.Apps` | 应用列表、详情、授权、安装/卸载/提取 APK |
| `Host.Modules` | 模块列表、刷入、开关、卸载、执行 action.sh |
| `Host.Ui` | Toast、消息框、确认框、输入框、文件/文件夹选择、保存框、进度 |
| `Host.Settings` | 插件专属 JSON 设置，自动保存 |
| `Host.Log` | 写插件日志（同时进宿主运行日志） |
| `Host.Events` | 设备连接变化、文件选中变化 |
| `Host.DataDirectory` | 插件专属数据目录（已创建） |
| `Host.SetHeader / SetStatus` | 更新插件页顶部（副标题 / 徽标 / 状态），见 §0.1 |

关键方法：

```csharp
// 设备端 shell（默认 root；root=false 用 shell 身份）
PluginShellResult r = await Host.Device.ShellAsync("pm list packages", true, ct);
int code = r.ExitCode;
string stdout = r.StdOut, stderr = r.StdErr;

// 不经过 shell 的 argv 执行（参数里有空格/引号时更安全）
var r2 = await Host.Device.ExecAsync("pm", new[] { "list", "packages" }, false, ct);

// 二进制安全读写
byte[] data = await Host.Device.ReadBytesAsync("/data/local/tmp/a.bin", ct);
await Host.Device.WriteBytesAsync("/sdcard/a.bin", data, ct);

// 把电脑文件推到 /data/local/tmp，返回远端路径（已 chmod 644）
string remote = await Host.Device.PushTempFileAsync(@"C:\tools\busybox", ct);

// 文件页选中项
PluginTarget? target = Host.Files.SelectedTarget;
if (target?.Kind == PluginTargetKind.File)
    await Host.Files.DownloadAsync(target.Path, @"C:\temp\out.bin", ct);

// UI（都在 UI 线程执行）
await Host.Ui.ShowMessageAsync("标题", "内容", ct);
bool ok = await Host.Ui.ConfirmAsync("确认", "继续吗？", "继续", "取消", ct);
string? text = await Host.Ui.PromptAsync("输入", "包名", "com.example", ct);
string? local = await Host.Ui.OpenFileAsync("选择 APK", "*.apk");
string? dir = await Host.Ui.PickFolderAsync("选择保存目录");
```

> **线程规则**：页面控件必须在 UI 线程创建。`CreateViewAsync` 由宿主在 UI 线程调用；
> 后台任务里要改 UI 时用 `Host.Ui.RunOnUiThread(...)`，或 `await Host.Ui.RunOnUiThreadAsync(...)`。

## 5. 修改宿主 UI（资源覆盖）

插件不需要改 XAML 就能改现有界面：主题色、圆角、行高等都是动态资源。

```csharp
// 覆盖单个颜色
Host.Ui.OverrideResourceColor("Accent", Color.Parse("#F5C451"));

// 覆盖任意资源（CornerRadius / double / IBrush …）
Host.Ui.OverrideResource("RadiusCard", new CornerRadius(22));
Host.Ui.OverrideResource("RadiusCtl", new CornerRadius(14));

// 恢复本插件做过的所有覆盖
Host.Ui.ClearResourceOverrides();
```

- 覆盖只在当前插件生命周期内有效；禁用/重载插件时宿主会自动恢复。
- `OverrideResource` 返回 `IDisposable`，也可以只恢复某一项。
- 主题资源键见 `App.axaml`：`Accent*`、`Panel*`、`RadiusCard`、`RadiusCtl`、`RowH` 等。
- 示例：`samples\ThemeStudioPlugin`。

> 注意：应用设置里切换主题色会重新写入资源；插件可以在自己的页面里再次覆盖。

## 6. 页面（PluginPage）

```csharp
Host.AddPage(new PluginPage
{
    Id = "analysis",
    Title = "分析",
    Icon = "🔍",
    Description = "APK / DEX 分析",
    CreateViewAsync = async (host, ct) =>
    {
        var panel = new StackPanel { Spacing = 8, Margin = new Thickness(16) };
        var output = new TextBox { IsReadOnly = true, AcceptsReturn = true };
        panel.Children.Add(new Button
        {
            Content = "开始分析",
            Command = /* 你自己的 ICommand，或直接挂 Click */ default,
        });
        panel.Children.Add(output);
        return panel;
    },
});
```

- 宿主**缓存页面控件**：切走再切回不会重建，滚动位置与页面内状态都保留。
- 页面按 `AddPage` 的注册顺序显示；超过 1 个页面时插件页顶部会出现滑动标签条（见 §0.1）。
- 快速写法：`PluginPage.FromControl(id, title, host => new MyView(host), description, icon)`。
- 插件页里不要再画一遍插件名/版本（外壳已有），用 `Host.SetHeader` 补充能力标签与状态。

## 7. 右键动作（PluginAction）

```csharp
Host.AddAction(new PluginAction
{
    Id = "hash-file",
    Title = "计算 SHA-256",
    Description = "对选中的文件计算哈希",   // 可省略
    Icon = "🔒",                            // 可省略
    Targets = new[] { PluginTargetKind.File, PluginTargetKind.Directory },
    ExecuteAsync = async (target, ct) =>
    {
        var r = await Host.Device.ShellAsync("sha256sum " + PluginShell.Quote(target.Path), true, ct);
        await Host.Ui.ShowMessageAsync("SHA-256", r.StdOut, ct);
    },
});
```

- `Targets` 决定菜单出现在哪里：`File` / `Directory` / `App` / `Module` / `Global`。
- 多个插件的动作会按插件名分组；只有你自己一个插件时直接平铺。
- 动作里抛异常会被宿主捕获并提示，不会让整个菜单崩掉。

## 8. 打包与版本

`.dfp` 就是改了扩展名的 zip，**根目录**直接是 `plugin.json` + 入口 dll（+ 可选 LICENSE）：

```
com.example.myplugin.dfp
  plugin.json
  MyPlugin.dll
  LICENSE（建议）
```

`build\build-plugins.ps1` 会构建 `samples\*` 下的插件并同时产出展开目录与 `.dfp`。

- 改了插件代码：重新构建 → 插件页「安装 .dfp」覆盖，或「重新加载」；
- 宿主 API 有新增时看本文件的 §0.1 与 `PluginContracts.cs`；
- 交付前用 `dotnet build -c Release` 编一次，确认 `apiVersion` / `minHostVersion` 与实际宿主匹配。


## API v2：插件主导航与运行保护

v2 是能力版本，旧 API v1 插件仍可加载；API 程序集的 AssemblyVersion 保持 1.0.0.0。使用以下能力的插件必须声明 `apiVersion: 2`，旧宿主会明确拒载并提示升级。不能只替换旧宿主的 API DLL：还需要本次的主导航和生命周期实现。

```csharp
Host.AddPage(new PluginPage {
    Id = "partition-flash", Title = "分区刷写",
    ShowInMainNavigation = true, NavigationOrder = 100,
    CreateViewAsync = (_, ct) => Task.FromResult<Control>(new FlashPage { DataContext = session })
});
```

主导航扩展统一插在“设置”前，按 NavigationOrder、PluginId、PageId 排序。禁用、卸载、重载时自动更新；被移除的选中页返回“插件”。内置 SelectedTab 的 0–5 不变，视图通过 NavigationIndex 做位置映射。工厂必须每次返回**新 Control**：插件管理页和主导航页独立承载，同一个 Control 不能有两个父节点；可以共享操作会话 ViewModel。

长时间设备操作应额外实现 `IPluginOperationGuard`。当 IsOperationActive 为 true，宿主阻止该插件禁用/卸载/重载，阻止全插件重载/安装和正常窗口关闭。任务确认期间也应保持 busy。不要在任务后台还运行时提前返回 idle。正常关闭保护不能阻止系统关机、进程被强制结束或 USB 断开。

Fastboot 示例将读操作设为可取消；写操作不强杀进程，“停止后续任务”仅在当前原生命令结束后生效。整包 update 内部可能包含多个任务，它作为一个不可拆开的命令处理。跨实例文件锁避免另一个插件会话同时刷写/回读；这不能约束用户在外部终端启动的其他工具。
